## 0.1 路线定义（★逻辑层——路线先于代码存在，2026-08-16 重构）

> 路线的区分建立在「引擎如何决定加载一场战斗」的**逻辑**上，不依赖具体地址。
> 代码（地址/hook/注入）只是路线的实现手段；换地址不换路线。全文件机制小节均标注归属：**[①] = 路线1 / [②] = 路线2 / [共] = 共用基础**。

### 路线1：AI 自身姿态触发加载（外部注入驱动加载机器）

- **逻辑依据**：引擎存在一台「战斗加载机器」（battle_mgr 创建链），它有一个**入口条件**——只有某参战方被识别为「人类」时机器才会被驱动。AI 内战默认没有人类参战方 → 机器不启动 → 走自动结算。路线1 = 用外部注入人为满足入口条件（哪怕数据足迹不完整），强行把加载机器驱动起来。
- **目标**：battle_mgr 创建 + 进入场景加载。允许伴随卡死/崩——那是「注入不完整」的症状，可逐个补。
- **完成标准**：注入后引擎走加载流程，最终 battle_mgr 创建、不崩。
- **手段家族**：0x6084db 转人类注入、双转人类、直调 wrapper、伪造 iface、pending 状态旁路、AI 分支原生门（G1-G4/case2）激活。
- **现状**：钥匙（1-A 单转人类）✅ 半通 → **状态 10 双门证伪（2026-08-15 re_f8 静态确证：非加载门，是 AI 开战链尾部检查）→ 1-A-2/1-A-3 双转路线关闭**；AI 原生门（1-D/1-E）⬜ 未探。**主攻转路线2 P6（复现状态 4）**。

### 路线2：仿照人类存在（完整伪造「有人类参战」的数据足迹）

- **逻辑依据**：引擎原生态支持「AI 战 + 人类援军加入」——进攻/防守都是 AI，只要人类援军参与，战斗照常加载。这证明引擎判定「是否加载」的依据 = 「存在被识别为人类的参战方」这一**数据足迹**，不是「操作者身份」。路线2 = 完整复现「人类存在」的数据足迹，让 AI 内战在引擎看来与「有人类参战」完全等同。
- **★援军本质（2026-08-18 用户纠正，替代旧表述「加载后援军加入」）**：援军不是「战斗加载后人类军队顺带加入」，而是 **AI 独立进攻 → 恰巧周围有人类部队（非参战、无需操作）→ 才触发战斗加载**（弹出战前选择界面：自动战斗/手动战斗/不参与）。它标志 **AI 在一定信号下可独立触发战前选择界面**——该界面本质 = **自动战斗路线 / 手动加载路线 / AI 独立结算路线的集合体**（三路线在引擎内由同一选择节点分叉）。→ **「人类部队在场」（仅存在、不参战）就是足够强的加载信号**，比「伪造参战方 faction+0x6a0」弱得多、也本质得多 → **路线2 的 2-B 伪造援军 / 2-C 伪造观察者形态在引擎里有原生触发机制**（战场格/军队在场判定，待定位）。
- **★「完全伪造人类存在」是唯一正确方向（2026-08-18 用户认知定案）**：伪造失败 = 「人类通了，但偏离人类发生的情况、只伪造链条后段」（例：v4-complete 只伪造登记门控三字节，但「人类参战方存在」源头未发生 → 分叉不运行 → 状态 4 永不到达）。**要打通 = 在 AI 战斗最早信号点，完整伪造「人类存在」的全部足迹**（参战方名单 +0x60/+0x64、本地玩家、军队在场、登记门控、分叉判定——全集待定位）。人类路径是引擎内建（K4 实机全通）→ 存在性保证 → 路线2 不可能封死，只可能「足迹未伪造全」。
- **目标**：AI 内战加载，且不依赖注入副作用（不卡死、不崩）——引擎自己认为「这场战斗有人类」。
- **完成标准**：AI 内战以与「人类参战」无差异的方式加载出战斗场景。
- **手段家族**：[pending+0x54] 归零 → 状态 4（人类等待态）、人类足迹信息伪造全集（参战方名单/军队在场/登记门控/分叉判定）。
- **现状**：**v4-complete（登记门控三字节直写）已实机证明「登记门控能过」✅（2026-08-18：6a0/798/7a0 全写 1 + pre=17→post=33 + 同 tick 去重正常）→ 但 fork（0x6045cc）全程 0 触发 → 状态 4 不可达 → 登记路在「后段直写」形态下不通**；★2026-08-18 六路静态定案修正：**fork 0 触发 = 观测窗口伪像 + 分叉输入（ready/条目+0xd）未伪造**——AI 内战确实经过状态 1 分叉（P6 基线 word54 0→1 = 返回 1 → 状态 6 → 状态 10；03 line 1008「AI 内战永不激活 setup」修正为「分叉返回 1」）；**伪造必须早于 pending 构造**（登记在 0x5abf3d 构造链内，0x6084db 时点太晚）→ 正解 = T0 构造前注入 + 0x6084db 三重建点 + offer 链伪造（详见 §7.2）；→ 路线2 剩余通路 = ①在更上游伪造「人类参战方存在/军队在场」（战前选择界面触发信号）②0x6084db 人类分支（路线1 已验证点，AI 内战结算路径确实经过它）③援军/观察者足迹伪造。

## 10. 重要教训（实验纪律）

1. **★路线归属纪律（2026-08-16 新增）**：每次对话开头声明**在打通路线1（[①] AI 姿态+注入）还是路线2（[②] 仿照人类存在）**；归属判据 = 改注入/旁路/驱动加载机器 → [①]，观测/复现/伪造人类足迹 → [②]。**禁止把 [①] 手段当 [②] 目标追**（单/双转人类是 [①] 手段，不是"仿照人类"——此前混线导致反复混乱）。
2. **卡死 = 外部读优先**（进程活着 = 免费数据源，unstick --peek 只读诊断），不要先加 hook 猜；伪造完成（--done/--cd）已证 UAF 崩，不用于加载目的。
3. **状态 3 不是卡死判据**（人类战斗也停 3）；判据 = 类型 6 节点 &3=2 且状态不变。
4. **observe 的 branch 重写是保真的**（验证过与原始目标一致）；observe 是零行为影响。
5. **注入版会污染引擎上下文**（状态 6 必退）——注入只用于"触发后观察"，不能常驻。
6. **M40 类入口 hook 抓参要确认参数传递约定**（0xea7ed0 的 param_1 在 [esp+4]，ecx 是垃圾）。
7. **stub 判定方向必须离线验证**（0x6084db v1 把 +0x6a0 判定写反，转人类从未生效——实机 stub 反汇编才暴露）；跳转 rel 计算、pushad 栈偏移（[esp+0x1C]=eax）都要 capstone 自校验。
